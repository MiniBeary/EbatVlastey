# Исходные сертификаты

В комплекте два публичных DER-сертификата Минцифры, экспортированные из исходного установленного комплекта. Секретных ключей в них нет. Программа проверяет SHA-256 ресурса и SHA-1 отпечаток сертификата перед использованием. SHA-1 здесь служит идентификатором сертификата; целостность файла проверяется SHA-256.

| Ресурс | Название | SHA-1 | SHA-256 |
|---|---|---|---|
| rsa.cer | Russian Trusted Root CA | 8FF915CCAB7BC16F8C5C8099D53E0E115B3AEC2F | D26D2D0231B7C39F92CC738512BA54103519E4405D68B5BD703E9788CA8ECF31 |
| gost.cer | Минцифры России НУЦ корневой | 656F78A4649A650E54043043B1C5EEEC128704A9 | 5B51DB721B7C34958ED7432AE917A91297DD37508B2CAE4F858FFBAC6BC525EF |

Первый сертификат использует RSA и истекает 28 февраля 2032 года по московскому времени; второй использует ГОСТ и истекает 24 мая 2040 года. Новый корень и обе ограниченные версии ограничены более ранним сроком.

Официальная страница распространения: [Госуслуги — TLS](https://www.gosuslugi.ru/tls). Проект фиксирует именно указанные файлы, а не любую будущую загрузку с этой страницы. Замена ресурсов требует нового осознанного выпуска и обновления отпечатков.

У ограниченных версий сохраняются байты имени владельца, алгоритм публичного ключа, параметры и публичный ключ исходного сертификата. Переносятся исходные расширения, кроме Authority Key Identifier и Name Constraints. Новый AKI указывает на созданный корень; критический Name Constraints допускает `.ru`, `.su`, `.xn--p1ai` и исключает все IPv4/IPv6.

Новый корень, ограниченные версии и сертификаты проверки содержат только публичные данные при записи на диск. Тестовые сертификаты действуют недолго; повторная проверка их цепочек использует сохранённое время создания, а срок установленного корня дополнительно проверяется по текущему времени.

Чтение хранилищ различает физическое хранилище пользователя и унаследованные/управляемые записи. Сравнение исходных корней выполняется по публичному ключу, а не только по названию или отпечатку: повторный выпуск с тем же ключом также обнаруживается.

При первой установке корня используется обычное подтверждение Windows. Удаление и восстановление ранее одобренных записей выполняется через REG provider CryptoAPI в физических Root/CA текущего пользователя. Политики ProtectedRoots и системные настройки защиты не изменяются. Применение этого механизма на других сборках Windows требует испытания отмены и восстановления.
